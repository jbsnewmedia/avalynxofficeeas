# Release 1.0.2 - Changelog Summary

This maintenance release resolves the remaining findings of the security audit: devices authenticate with revocable app passwords instead of the web login password, the end-of-life MIME library is replaced by a dependency-free parser, authentication and bootstrap paths leak less information, and destructive device operations behave more conservatively.

- **App Passwords Instead of the Web Login Password (M16)**
  `UserResolver` no longer accepts `app_user.password`. Devices authenticate with an app password created by the user in the core (*Profile → App passwords*), stored as a `password_hash()` digest in the new core table `app_user_app_password`. Every active, non-revoked app password of the user is verified (constant work regardless of which one matches, dummy hash when there is none), input is normalized like the core does (dashes/whitespace optional, case-insensitive) and the last use is recorded in `last_used_at` (at most once per minute). Revoking an app password in the profile or resetting the web password cuts the device off at its next request.
  *Benefit: the web password never lives on a device, every device can be revoked individually, and a leaked device credential does not grant web access.*

- **MIME Parser Without EOL Dependency (M14)**
  `laminas/laminas-mail` 2.5.2 (unmaintained since 2015, pulled in by the `php >= 8.5` constraint) and its nine transitive `laminas/*` packages are removed. Messages submitted by devices (SendMail/SmartForward/SmartReply) are parsed by the new `AvalynxOfficeEas\Mail\MimeParser` / `MimePart` (RFC 822/2045/2046/2047/2231: header unfolding, encoded words, nested multiparts, quoted-printable/base64, charset normalization to UTF-8, address lists, RFC 2231 file names). From/To/Cc/Bcc/Reply-To, subject, text and HTML bodies and attachments are extracted as before; the From check against the account address is unchanged.
  *Benefit: no unmaintained parsing code on the input path of untrusted device data, and a smaller dependency footprint.*

- **Attachment Limit Is Enforced, Not Silent (N9)**
  Attachments above `ATTACHMENT_STORAGE_MAX_BYTES` were dropped silently and the message was queued without them. The submission now fails with `SYNC_COMMONSTATUS_MAILSUBMISSIONFAILED` and a logged warning, nothing is stored. The default limit is raised from 64 KB to 25 MB (`26214400`) and documented in `.env.example` and the README.
  *Benefit: the device shows a send error instead of a recipient receiving an incomplete message.*

- **Empty Folder Moves to the Wastebasket (N5)**
  `EmptyFolder` deleted messages permanently from any folder. It now mirrors `DeleteMessage`: emptying a regular folder moves the mails into the Papierkorb, only emptying the Papierkorb itself removes them permanently.
  *Benefit: an accidental "empty folder" on a device is recoverable.*

- **Hardened Authentication and Bootstrap (N1, N4, N7)**
  Unknown users are verified against a dummy bcrypt hash so the response time no longer reveals whether an e-mail address exists. The service bootstrap in `public/index.php` is wrapped: configuration or database failures are written to `error_log` and answered with a generic `503 Service Unavailable` instead of a PHP error page. Seat activity timestamps (`app_user.last_auth_at`) are written explicitly in UTC, matching the core.
  *Benefit: no user enumeration via timing, no internal details in error responses, consistent seat accounting across core and plugin.*

- **Consistent Environment and Permissions (N2, N3)**
  State, log and attachment directories are created with `0770` instead of `0777`. The `.env` loader mirrors values into `$_SERVER` and the Z-Push configuration and `EndpointService` read `EAS_STATE_DIR`, `EAS_LOG_DIR` and `EAS_LOGLEVEL` through `Database::env()`, so `.env` based setups and real environment variables behave identically (existing variables are never overwritten).
  *Benefit: no world-writable runtime directories, and `.env` settings for Z-Push actually take effect.*

- **No Display-Name Poisoning of the Shared Address Pool**
  When a device submitted a message, `SendMailService` copied the display name from the From/To/Cc/Bcc/Reply-To header onto the globally shared `Address` row if it had none yet — so one user's device could choose the name that every other account sees for that e-mail address. Display names from device-submitted messages are no longer persisted; addresses are linked by e-mail only and existing names stay untouched (`AccountAddress` carries no per-account name).
  *Benefit: a client-controlled header can no longer rename an address for all users of the installation.*

- **Brute-Force Throttle Keyed by the Edge Proxy's Client IP, Plus Per-User Counter**
  `AuthThrottle` used the client-controlled `X-Forwarded-For` header, so an attacker could pick a fresh "IP" for every attempt. The throttle now reads `X-Real-IP`, which the edge proxy overwrites on every request (`USE_CUSTOM_REMOTE_IP_HEADER=HTTP_X_REAL_IP` in the Z-Push configuration makes Z-Push log and evaluate the same address), and additionally counts failures per normalized username. The limits are separate: 10 failures per IP and 50 failures per user within 300 seconds — the per-user limit is deliberately higher so that a known username cannot be locked out by a handful of requests from changing addresses (lockout DoS). A successful login clears both counters.
  *Benefit: brute force is throttled by a value the attacker does not control, without turning the throttle into a denial-of-service tool against legitimate users.*

- **From Header Restricted to the Account Address**
  A device could submit a message with an arbitrary `From` header. `SendMailService` now only links `From` addresses that match the account's own e-mail address and falls back to the account address when none matches; the core queue therefore never sees a foreign sender.
  *Benefit: no sender spoofing through the EAS endpoint.*

- **Contact Scoping and Copy-on-Write for Shared Addresses**
  `Address` rows are shared between accounts (contacts and mail addresses). A contact update from one device could previously rewrite a row that other accounts reference — including its `email` column, i.e. the address shown in other users' mails. `ContactService::update()` now only touches the account's own `AccountAddress` link and copies the row before editing whenever it is still referenced elsewhere: by another account's contact link **or by an `EmailAddressLink` of a mail that belongs to another account**. `delete()` removes only the account's own link and drops the `Address` row only when no further contact or mail links exist.
  *Benefit: a device can edit or delete its own contacts without altering what other users see.*

- **Stack Traces and Internal Error Messages Stay in the Log**
  `EndpointService::handleException()` used to return the exception message — and until 1.0.1 even the stack trace — in the HTML error page. For non-Z-Push exceptions (Doctrine/PostgreSQL errors, PHP errors) the response now carries only a generic `Internal server error`; message and trace are written to the Z-Push log at `LOGLEVEL_ERROR`. Z-Push's own exceptions keep their intended, client-facing messages.
  *Benefit: schema, connection or file-system details no longer leak to unauthenticated clients.*

- **Hardened Message Submission (SendMail)**
  `AvalynxBackend::SendMail()` catches every `Throwable` (not only `RuntimeException`), logs class and message and reports `SYNC_COMMONSTATUS_MAILSUBMISSIONFAILED` to the device. Before values reach the database `SendMailService` strips NUL bytes, repairs invalid UTF-8 and truncates to the column length (subject and message-id 255, attachment name 255, MIME type 190, address 190). E-mail addresses are lower-cased and must pass `filter_var(FILTER_VALIDATE_EMAIL)`; an invalid recipient aborts the submission. The size limit `ATTACHMENT_STORAGE_MAX_BYTES` now also applies to the sum of all attachments of one message, `MimeParser` rejects messages above 64 MiB (`MAX_INPUT_BYTES`) or with more than 200 MIME parts (`MAX_PARTS`), duplicated header parameters use the first value (`Content-Type`/`Content-Disposition`), and only an allowlist of real character sets (UTF-8, US-ASCII, ISO-8859-*, Windows-125*, KOI8-R/U, GB2312/GBK/GB18030, Big5, Shift_JIS, EUC-JP, EUC-KR, ISO-2022-JP, UTF-16/32) is passed to mbstring — anything else is treated as UTF-8 with a fallback cleanup. The image sets `PHP_POST_MAX_SIZE` and `PHP_UPLOAD_MAX_FILESIZE` to `64M`, matching the edge limit.
  *Benefit: a malicious device cannot crash the submission path with oversized or malformed MIME, poison the shared address table, or trigger database errors with invalid bytes.*

- **`app_user.password` Is No Longer Mapped**
  The `User` model no longer maps the `password` column (EAS authenticates exclusively with app passwords). The least-privilege database role `eas_user` therefore no longer needs `SELECT` on `app_user.password`; EAS reads `id`, `email`, `roles`, `active`, `last_auth_at`, `created_at` and `updated_at` and writes `last_auth_at`.
  *Benefit: the web password hash is unreadable for the plugin even if the EAS process is compromised.*

- **`.dockerignore`**
  `.env`, `var/`, `.git`, tests and tooling are excluded from the build context so they never end up in an image layer.

- **Quality Gates**
  New unit tests cover the MIME parser (multipart/alternative with attachment, UTF-8 subject, RFC 2231 file names, Reply-To, address list edge cases, malformed input, duplicate parameters, charset allowlist, size and part limits) and new backend integration tests cover multipart submission with attachment, the attachment limit, address validation/normalization, copy-on-write for addresses referenced by another account's mail and the new `EmptyFolder` semantics, run together with PHPStan level max, ECS and Rector via `composer ci`.
  *Benefit: the replaced parser and the changed destructive paths are covered by every push and pull request.*

**Compatibility**: Requires the core migration that adds `app_user_app_password`; the least-privilege EAS database role additionally needs `UPDATE (last_used_at)` on that table and may drop `SELECT` on `app_user.password` (applied by the compose stack / core entrypoint). The edge proxy must set `X-Real-IP` (the compose stack does). **Existing device profiles must be reconfigured with an app password** — the web login password is no longer accepted. `ATTACHMENT_STORAGE_MAX_BYTES` has a new default (25 MB) and now also limits the total of all attachments of a message; deployments that relied on the old 64 KB default should set the variable explicitly. Requests larger than 64 MB are rejected (`PHP_POST_MAX_SIZE`). Recipients that are not valid e-mail addresses are rejected with `MailSubmissionFailed`. `EmptyFolder` on non-wastebasket folders is now a move instead of a hard delete.
