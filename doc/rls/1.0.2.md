# Release 1.0.2 - Changelog Summary

This maintenance release resolves the remaining findings of the security audit: devices authenticate with revocable app passwords instead of the web login password, the end-of-life MIME library is replaced by a dependency-free parser, authentication and bootstrap paths leak less information, and destructive device operations behave more conservatively.

- **App Passwords Instead of the Web Login Password (M16)**
  `UserResolver` no longer accepts `app_user.password`. Devices authenticate with an app password created by the user in the core (*Profile → App passwords*), stored as a `password_hash()` digest in the new core table `app_user_app_password`. Every active, non-revoked app password of the user is verified (constant work regardless of which one matches, dummy hash when there is none), input is normalized like the core does (dashes/whitespace optional, case-insensitive) and the last use is recorded in `last_used_at` (at most once per minute). Revoking an app password in the profile or resetting the web password cuts the device off at its next request.
  *Benefit: the web password never lives on a device, every device can be revoked individually, and a leaked device credential does not grant web access.*

- **MIME Parser Without EOL Dependency (M14)**
  `laminas/laminas-mail` 2.5.2 (unmaintained since 2015, pulled in by the `php >= 8.5` constraint) and its nine transitive `laminas/*` packages are removed. Messages submitted by devices (SendMail/SmartForward/SmartReply) are parsed by the new `AvalynxOfficeEas\Mail\MimeParser` / `MimePart` (RFC 822/2045/2046/2047/2231: header unfolding, encoded words, nested multiparts, quoted-printable/base64, charset normalization to UTF-8, address lists, RFC 2231 file names). From/To/Cc/Bcc/Reply-To, subject, text and HTML bodies and attachments are extracted as before; the From check against the account address is unchanged.
  *Benefit: no unmaintained parsing code on the input path of untrusted device data, and a smaller dependency footprint.*

- **Attachment Limit Is Enforced, Not Silent (N9)**
  Attachments above `ATTACHMENT_STORAGE_MAX_BYTES` were dropped silently and the message was queued without them. The submission now fails with `SYNC_COMMONSTATUS_MAILSUBMISSIONFAILED` and a logged warning, nothing is stored. The default limit is raised from 64 KB to 25 MB (`26214400`) and documented in `.env.example` and the README.
  *Benefit: the device shows a send error instead of a recipient receiving an incomplete message.*

- **Empty Folder Moves to the Wastebasket (N5)**
  `EmptyFolder` deleted messages permanently from any folder. It now mirrors `DeleteMessage`: emptying a regular folder moves the mails into the Papierkorb, only emptying the Papierkorb itself removes them permanently.
  *Benefit: an accidental "empty folder" on a device is recoverable.*

- **Hardened Authentication and Bootstrap (N1, N4, N7)**
  Unknown users are verified against a dummy bcrypt hash so the response time no longer reveals whether an e-mail address exists. The service bootstrap in `public/index.php` is wrapped: configuration or database failures are written to `error_log` and answered with a generic `503 Service Unavailable` instead of a PHP error page. Seat activity timestamps (`app_user.last_auth_at`) are written explicitly in UTC, matching the core.
  *Benefit: no user enumeration via timing, no internal details in error responses, consistent seat accounting across core and plugin.*

- **Consistent Environment and Permissions (N2, N3)**
  State, log and attachment directories are created with `0770` instead of `0777`. The `.env` loader mirrors values into `$_SERVER` and the Z-Push configuration and `EndpointService` read `EAS_STATE_DIR`, `EAS_LOG_DIR` and `EAS_LOGLEVEL` through `Database::env()`, so `.env` based setups and real environment variables behave identically (existing variables are never overwritten).
  *Benefit: no world-writable runtime directories, and `.env` settings for Z-Push actually take effect.*

- **Quality Gates**
  New unit tests cover the MIME parser (multipart/alternative with attachment, UTF-8 subject, RFC 2231 file names, Reply-To, address list edge cases, malformed input) and new backend integration tests cover multipart submission with attachment, the attachment limit and the new `EmptyFolder` semantics — 33 tests in total, run together with PHPStan level max, ECS and Rector via `composer ci`.
  *Benefit: the replaced parser and the changed destructive paths are covered by every push and pull request.*

**Compatibility**: Requires the core migration that adds `app_user_app_password`; the least-privilege EAS database role additionally needs `UPDATE (last_used_at)` on that table (applied by the compose stack / core entrypoint). **Existing device profiles must be reconfigured with an app password** — the web login password is no longer accepted. `ATTACHMENT_STORAGE_MAX_BYTES` has a new default (25 MB); deployments that relied on the old 64 KB default should set the variable explicitly. `EmptyFolder` on non-wastebasket folders is now a move instead of a hard delete.
