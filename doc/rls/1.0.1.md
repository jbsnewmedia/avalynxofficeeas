## Release 1.0.1 – Changelog Summary

Maintenance release of **avalynxofficeeas**, the ActiveSync (EAS) extension
for AvalynxOffice — adds Active Seat support for device synchronization.

* **Active Seat Support (APL 1.0)**
  Every successful device login (`Logon()`) refreshes the seat activity
  timestamp `app_user.last_auth_at` via the new
  `AvalynxOfficeEas\Service\LastAuthenticationRecorder`. Accounts that only
  synchronize over ActiveSync keep their Active Seat under the AvalynxOffice
  Public License (APL 1.0); the seat accounting itself stays in the core.
  The write is throttled (at most once per hour) — devices authenticate on
  every sync request, so no extra write load per request. A failing
  accounting write is logged as a warning and never blocks the sync.
* **Shared-Schema Extension**
  The plugin's own `User` model maps the new `app_user.last_auth_at` column
  (the database schema remains the interface — no core code is used). The
  column is created by the AvalynxOffice core migration
  `Version20261016080000`.
* **Quality Gates**
  Four new backend integration tests cover the seat activity recording
  (success, stale refresh, throttle, failed logon) — 17 tests in total.

**Compatibility**: Requires an AvalynxOffice core with the licensing schema
including `app_user.last_auth_at` (core migration `Version20261016080000`).
Against older cores the plugin keeps working — the recorder logs a warning
and device synchronization is unaffected.
