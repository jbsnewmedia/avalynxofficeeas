# Release 1.0.1 - Changelog Summary

This maintenance release adds Active Seat support for device synchronization: every successful device login refreshes the seat activity timestamp, so accounts that only synchronize over ActiveSync keep their seat under the AvalynxOffice Public License (APL 1.0).

- **Active Seat Support (APL 1.0)**
  Every successful device login (`Logon()`) refreshes the seat activity timestamp `app_user.last_auth_at` via the new `AvalynxOfficeEas\Service\LastAuthenticationRecorder`. The seat accounting itself stays in the AvalynxOffice core — the plugin only records the activity.
  *Benefit: accounts that only synchronize over ActiveSync keep their Active Seat — no separate web login required.*

- **Throttled Recording**
  Devices authenticate on every sync request, so the timestamp write is throttled to at most once per hour (single atomic conditional `UPDATE`). A failing accounting write is logged as a warning and never blocks the synchronization.
  *Benefit: no extra write load per request, and device sync keeps working even while the seat accounting is temporarily unavailable.*

- **Shared-Schema Extension**
  The plugin's own `User` model maps the new `app_user.last_auth_at` column — the database schema remains the interface, no core code is used (AGPL aggregation boundary). The column itself is created by the AvalynxOffice core migration `Version20261016080000`.
  *Benefit: web login (core) and device sync (plugin) feed the same seat activity source.*

- **Quality Gates**
  Four new backend integration tests cover the seat activity recording (success, stale refresh, throttle, failed logon) — 17 tests in total, run together with PHPStan level max, ECS and Rector via `composer ci`.
  *Benefit: the licensing-relevant behavior is covered by every push and pull request.*

**Compatibility**: Requires an AvalynxOffice core with the licensing schema including `app_user.last_auth_at` (core migration `Version20261016080000`). Against older cores the plugin keeps working — the recorder logs a warning and device synchronization is unaffected. No configuration changes are needed.
